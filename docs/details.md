# Подробности к README

## Поиск

Три варианта сравнили на 30 перефразированных клинических запросах (`data/eval/retrieval_gold.jsonl`, ноутбук 01):

| | Recall@5 | Recall@10 | MRR@10 | nDCG@5 |
|---|---|---|---|---|
| BM25 (pymorphy3 + раскрытие сокращений) | 0.778 | 0.861 | 0.584 | 0.602 |
| Dense `deepvk/USER2-base` | 0.817 | 0.850 | 0.665 | 0.691 |
| **Hybrid (RRF)** | **0.861** | **0.961** | **0.691** | **0.692** |

Planner ищет в пределах разделов своей клинической области и подзапросами по подтемам (например, АСК и ингибитор P2Y12 отдельно), выдача подтем чередуется. Один общий запрос на область терял тезис про АСК.

## Цепочка промптов вместо вызова инструментов

Поиск вызывает код, а не LLM: planner проходит 7 клинических областей, для каждой делает подзапросы с фильтром по разделу КР и передаёт найденные фрагменты в промпт. Так прогон воспроизводим и кэшируется, контекст каждой области ограничен её разделами КР, а маленькие бесплатные модели не должны сами решать, что искать: вызов инструментов у них нестабилен.

## Защита от галлюцинаций

- Назначение попадает в план, только если `chunk_id` был в контексте, цитата дословно есть в чанке (допустим пропуск уточнений в скобках и фрагментов через «…»), а название препарата и каждое число дозы есть в процитированном тексте.
- Пересказ одного предложения чанка (token_set ≥ 85) заменяется дословным предложением КР с пометкой «выровнена», выдуманные формулировки отклоняются.
- Детерминированные защиты: нет ЛС из группы аллергена, не больше одного ингибитора P2Y12 и одного парентерального антикоагулянта, нет дублей.
- Не прошедшее проверку назначение получает одну попытку исправления, затем помечается `unsupported` и получает находку R7.
- Проверка полноты (`mandatory.py`): если в плане нет группы, которую КР рекомендует этому пациенту, LLM отдельным запросом дополняет план с цитатой или не добавляет её при противопоказании. Всем: АСК, ингибитор P2Y12, статин, иАПФ (при непереносимости - АРА). При ФВ ЛЖ ≤ 40%: бета-адреноблокатор, а при СН или СД - антагонист альдостерона, если креатинин ≤ 220 (м) / 175 (ж) мкмоль/л и K⁺ ≤ 5,0. Те же группы проверяет правило R16.

## Динамика

Формулы, а не LLM, всё воспроизводимо (seed): тропонин - кинетика «подъём-спад»; креатинин и рСКФ (CKD-EPI 2021) реагируют на контраст с учётом контраст/рСКФ, СД, возраста и гидратации из плана (гидратация снижает риск ОПП в 2,5 раза); Hb зависит от числа антитромботиков, K⁺ - от рСКФ, блокаторов РААС и антагонистов альдостерона.

## Аудитор

- 14 правил цитируют КР дословно (цитаты проверяются тестом): противопоказания по рСКФ, контраст и гидратация, согласие, ИПП и взаимодействия, аллергии, НПВП, антикоагулянт после ЧКВ (продолженный > 24 ч или начатый после ЧКВ), выбор P2Y12 и гидратация вне условий тезиса, упущения обязательных групп.
- LLM-аудитор (Nemotron 3 Ultra) ищет то, что правилами не формализовано. Его находки проходят проверку ссылок и должны опираться на факт из трека.
- Затем вторая модель (Qwen3.8-27B) проверяет каждую находку по процитированному тезису и треку: выполнены ли условия тезиса у пациента и верен ли факт. Неподтверждённые находки не входят в отчёт, а показываются отдельным списком «отклонено проверкой» с причиной.

## Выбор LLM

На бесплатном плане Mistral `mistral-small`/`medium` отвечали 429, `mistral-large` - 403. Рабочая `ministral-14b-latest` не учитывала условия тезисов (нет иАПФ в case1, клопидогрел без показаний, гидратация при рСКФ 92, периндоприл при ангиоотёке на иАПФ), а в роли аудитора называла ошибкой отмену фондапаринукса после ЧКВ, которую требует КР.

Бесплатные модели OpenRouter и Groq отобрали по строгому JSON по схеме, отключаемому thinking, лидербордам галлюцинаций (AA-Omniscience, Vectara) и IFBench. Финалисты с выключенным thinking решали задачу аудита по фрагментам КР на русском: найти 2 нарушения и дать `chunk_id` с дословной цитатой.

| Модель, провайдер | Время | Результат |
|---|---|---|
| **Qwen3.8-27B, Groq** → planner, replanner, проверка находок | 1.5 с | 2/2, ссылки и цитаты дословные |
| Qwen3.8-27B, OpenRouter free | 1 с | пустой ответ без рассуждений, частые 429 |
| **Nemotron 3 Ultra 550B, OpenRouter free** → LLM-аудитор | 7-50 с | 2/2, цитаты дословные |
| Gemma 4 31B, OpenRouter free | - | 429 у провайдера |

Аудитор и проверяющая модель из разных семейств, поэтому их ошибки не совпадают.

Клиент (`llm/client.py`): модель задаётся строкой `провайдер:модель`; JSON по строгой схеме, а если модель её не поддерживает - через вызов инструмента; thinking отключён (Groq `reasoning_effort: "none"`, OpenRouter `reasoning.enabled: false`); при 429 клиент ждёт сброса лимита по `retry-after`. Ответы кэшируются в `data/llm_cache/` по хэшу модели, промптов и схемы, поэтому `LLM_MODE=replay` воспроизводит прогон без ключей.

## Структура кода

`src/resident/`: `kb/` (загрузка и разбор КР) · `retrieval/` (BM25 / dense / hybrid + оценка) · `llm/` (клиент с кэшем, промпты) · `citations.py` (проверка ссылок) · `mandatory.py` (обязательные группы ЛС) · `planner.py` · `simulator/` · `monitor.py` · `replanner.py` · `auditor/` (правила, LLM-аудит и проверка, отчёт) · `pipeline.py` · `schemas.py` (Pydantic-схемы всех этапов).

## Разбор результатов

**Планы.** Все назначения planner во всех кейсах прошли проверку ссылок. Проверка полноты добавила тикагрелор в case1 и case3 (модель назначила только АСК) и эплеренон в case2.

| Кейс | Лекарственные назначения planner |
|---|---|
| case1 | АСК, тикагрелор, эноксапарин (отменён после ЧКВ), метопролол, эналаприл, аторвастатин |
| case2 | АСК, клопидогрел, пантопразол, фондапаринукс (отменён после ЧКВ), бисопролол, валсартан, аторвастатин, эплеренон |
| case3 | АСК, тикагрелор, эноксапарин (отменён после ЧКВ), метопролол, аторвастатин, лизиноприл, инсулин |

**Пересмотр плана (case3, 72 ч).** Отклонения: ОПП (креатинин ×2,2), рСКФ 18 при эноксапарине, K⁺ 5,7, контраст/рСКФ 10,9 для этапного ЧКВ. Replanner отменил эноксапарин, этапное ЧКВ и лизиноприл, добавил гидратацию, НФГ и контроль электролитов (все ссылки подтверждены). Замену эноксапарина на НФГ после успешного ЧКВ, хотя промпт требует отменять без замены, поймало правило R13.

**LLM-аудитор и проверка находок.** Из 9 находок Nemotron проверка Qwen отклонила 6:

| Кейс | Принято | Отклонено (причина проверки) |
|---|---|---|
| case1 | - | ИПП не нужен (сам же пишет, что риска ЖКК нет); контроль креатинина по тезису для рСКФ 15-44 при рСКФ 92; доза метопролола по тезису об иАПФ |
| case2 | эналаприл при ангиоотёке (дублирует R5); омепразол с клопидогрелом (дублирует R4) | диклофенак со ссылкой на тезис о риске ЖКК, где нет запрета НПВП (сам дефект поймало R6) |
| case3 | лизиноприл отменён и не заменён - спорно: при K⁺ 5,7 и ОПП отмена иАПФ оправдана, а АРА и эплеренон тоже повышают калий | СД как фактор риска ЖКК (в тезисе его нет); гидратация и контраст/рСКФ < 3,7 по тезису для рСКФ 15-44 при рСКФ 48 |

В одном из промежуточных прогонов LLM-аудитор нашёл дефект вне правил - два ИПП одновременно (пантопразол по плану и омепразол из приёмного, case2). Вывод: правила - основной уровень, LLM дополняет, а без проверки второй моделью его шум был бы в отчёте.
